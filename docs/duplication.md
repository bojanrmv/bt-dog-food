# Duplication: `dgf duplication` and `dgf-dup`

`dgf duplication` (or `dgf dup`) finds code that can be united, and says how:
- code that is the same apart from names and values;
- near copies, with a statement added, left out or changed;
- the same statements in another order or mixed with other code;
- a long expression copied into different statements.

It is also its own tool, `dgf-dup`, which takes the same arguments (`crates/dog-food-dup`). `dgf duplication` reads the coverage reports `dgf.toml` names, so each group gets the CRAP score of its riskiest copy.

```powershell
cargo install --path crates/dog-food-dup --locked
dgf dup                        # the current folder, honoring .gitignore (or: dgf-dup)
dgf-dup backend --top 10       # the ten biggest wins
dgf-dup src --format agent     # compact text for AI assistants
dgf-dup src --format json      # everything, for other tools
dgf-dup src --format html -o dup.html   # a page: the files with their copies, and each group
dgf-dup src --fail-above 5     # exit 1 when more than 5% of lines are copies

dgf-dup --semantic             # also C# methods that do the same thing written differently (needs dgf-dup-cs)
dgf-dup --semantic --confirm   # and run each such group on generated inputs: one an input disproves is left out
dgf-dup --coverage TestResults # CRAP score of each group's riskiest copy; ranked by it (--rank saves|risk)
dgf-dup --changes              # only what this branch changed (since main, else master)
dgf-dup --changes --base origin/development --fail-on-copies   # a PR gate: exit 1 on any new copy
```

With `--changes`, the whole repository is still scanned, since a new copy is usually a copy of code the branch did not touch, but only groups with a copy in the branch's changed lines are reported (uncommitted edits and new files count). Changed copies are marked `(changed)`.

The HTML page is a review dashboard. It shows:
- what is open, reviewed and saveable, as numbers;
- the groups by kind of copy;
- the projects with the most duplicated lines, and the pairs of projects that share copies (click any of them to filter);
- a queue of groups to work through, with filters for kind, project, status, changed lines and text.

A group opens with its copies' code side by side, the lines only one of them has marked, then the template, holes, differences, rules and how to unite them.

Each group can be marked *to fix*, *intentional* or *false positive*, with a note. Keys `j`/`k` move, and `f`/`i`/`x`/`u` decide. A link to a group is `dup.html#group=<id>`. Decisions stay in the browser until **Export decisions** saves `dup-decisions.json`; **Import** loads one. Commit that file and pass it back:

```powershell
dgf-dup --decisions dup-decisions.json --format html -o dup.html   # reviewed groups left out, decisions shown
dgf-dup --changes --decisions dup-decisions.json --fail-on-copies  # a gate that only sees unreviewed copies
```

Groups decided as intentional or a false positive are left out (and counted). Groups to fix stay, and the agent format marks them `review: to-fix`. A group's id comes from its kind and the files and functions its copies are in. It stays the same while the code moves around inside those functions, so decisions survive later scans.

C#, TypeScript/JavaScript (also TSX/JSX) and Rust. Test code (`*.spec.ts`, `*Tests.cs`, `*.IntegrationTests` projects, `tests/`, `e2e/`, Rust `mod tests`) and migrations are left out unless `--tests` is given. Generated files are always left out: `*.g.cs`, `*.designer.cs`, and any file whose first lines say `<auto-generated>`, `@generated` or "generated … DO NOT EDIT".

## What a finding looks like

```
1. 2 copies of 10 lines (3 statements), type 2: renamed, saves about 6 lines
   src/Billing.cs:4-13   in Orders.Add
   src/Billing.cs:20-29  in Seats.Add
   template:
     | var total = 0m;
     | if (⟨1⟩.Active && ⟨1⟩.End > now)
     | {
     |     total += ⟨1⟩.⟨2⟩ * ⟨1⟩.Quantity;
     |     log.Add($"{⟨1⟩.Id} counted");
     | }
     | if (total > limit)
     | {
     |     total = limit;
     | }
   ⟨1⟩ name: plan | seat
   ⟨2⟩ member: Price | Fee
   ⟨3⟩ local: total | sum
   unite: extract a shared function in this file (a static helper the types call), taking ⟨2⟩ members; ⟨1⟩ variables (...)
   caution: the code after the first copy uses total: a shared version returns it

2. 2 copies of 8 lines (4 statements), type 3: near miss, 91% alike, saves about 3 lines
   src/Invoices.cs:40-47  in Invoices.Lines
   src/Receipts.cs:99-110  in Receipts.Lines
   template:
     | var rows = new List<string>();
     | foreach (var line in order.Lines)
     | {
     |     var amount = line.Quantity * line.Price;
     |     rows.Add(line.Sku + " " + line.Quantity + " " + amount);
     | }
     | rows.Sort(StringComparer.Ordinal);
     | return rows;
   differs: Receipts.Lines (line 102) adds `if (line.Quantity == 0) { continue; }`
   unite: the functions' bodies are alike apart from 1 edit: keep one function and pass what differs as a parameter, a flag or a delegate (...)

3. 8 statements in a row with one shape, saves about 11 lines
   src/Users.cs:55-77  in UserService.Update
   template:
     | if (dto.⟨1⟩ != null)
     |     user.⟨1⟩ = dto.⟨1⟩;
   ⟨1⟩ member: City | State | PostalCode | Country | ...
   unite: 8 statements in a row share this shape (23 lines): put what differs (⟨1⟩ members) in a list and loop over it, or call one helper 8 times
```

- **Type**:
  - 1, the same code;
  - 2, renamed (names, values or types differ);
  - 3, a near miss: whole function bodies whose tokens match for at least 80% of both, with statements or tokens added, left out or changed;
  - 3 with evidence `dependence`: the same statements with the same data flow, in another order or with other statements between them. The copy's lines are listed (`(lines 5-6, 8-11)`), and so are the statements between, which need moving out of the way before extracting it;
  - 4 (with `--semantic`, C#), the same behaviour written differently, with the rules that show it (`loop that adds up → Sum`, `switch → conditionals`) and the conditions they need.
- **Copies**: where each one is and the function it is in.
- **Template**: the first copy, with `⟨n⟩` wherever the copies differ. The same differences everywhere are one hole.
- **Holes** and what a shared version does with them: a *value* or *name* becomes a parameter, a *member* becomes a value or a selector (`x => x.Price`), a *call* becomes a function parameter, a *type* a generic parameter. A *local* the copy declares itself is only renamed and needs no parameter.
- **Unite**: keep one function (when whole bodies are copies), extract a private method (same type), a shared function (same file) or a shared helper (several files). A run of statements with one shape in a row (`if (dto.X != null) user.X = dto.X;` for every field) is reported once, with the advice to loop over a table of what differs.
- **Differs** (near misses): what each copy adds, leaves out or has instead, against the first copy, with its line. In the template, `⟪…⟫` marks what not every copy has.
- **Cautions**: values the code after a copy uses (the helper returns them), and `return`/`break`/`continue` inside a copy.
- **Saves**: the lines a shared version would remove, after its signature and calls. Findings are ranked by it, or with `--coverage` by risk.
- **Risk**: the cyclomatic complexity of the function holding the riskiest copy, and with `--coverage` its covered share and CRAP score. A complex, untested copy is where a fix made in one copy and missed in another hurts most, so `--rank risk` (the default with coverage) puts it first.
- **As a method** (C#, with `--semantic`): what the first copy takes and gives if extracted, from the compiler's data flow. It lists the locals and parameters it reads that are set before it, those it sets that are read after it, early `return`/`break`/`continue`, and whether it needs `this`. This is exact where the holes and cautions above are read off the tokens.
- **Confirmed** (type 4 with `--confirm`): the group's methods returned the same results on 1,000 generated inputs, or why they were not run.

## How it works

No AI, and no guessing: every step is exact on the syntax tree.

1. Each statement becomes its shape: keywords, operators and structure, with names and literals replaced by placeholders. Renamed copies have the same shapes.
2. The shortest run of statements from each position with at least `--min-tokens` tokens and `--min-lines` lines is a seed. Seeds with the same shapes form a group, and the group grows one statement at a time, splitting where its members' next statements differ. Every copy grows as far as another stays alike, with no pairwise comparison, so a pattern copied hundreds of times costs no more than its copies.
3. Equal runs form a clone class. These are left out:
   - a copy inside a bigger copy;
   - a copy that overlaps another copy of its class;
   - a class that only wraps a class with more copies;
   - a class whose copies all lie inside another class's copies of the same functions. So is a class with more than two parameters per statement: code that shares a shape but little else (mapping code, guard clauses on other fields).
4. Anti-unification of the copies' tokens gives the template: a hole at each position where their names or values differ, one hole per distinct set of differences.
5. A long expression inside a statement (a call chain such as a LINQ query, an object built with its members, a `switch` expression; three lines or more) is also a block of its own. So a copy of it is found where the statements around it differ: `var rows = query...;` in one method and `foreach (var row in query...)` in another. A copy found this way inside a copy of whole statements is not reported twice.
6. Reordered and interleaved copies: statements of two blocks are paired by shape, with one consistent renaming of locals (members and called functions keep their names). Only pairs whose data flows the same way are kept: every name a paired statement reads comes, in both copies, from partnered statements or from outside the copy. The largest group of paired statements linked by what they define and read is the copy, so statements that only look alike (a list of independent `builder.Property(...)` calls) are not one. Copies that are in order and side by side are left to the passes above.
7. Near misses (type 3) compare whole function bodies of at least 25 tokens (constructors, which are mostly wiring, are left out). Bodies that share enough runs of 8 normalized tokens are candidates. A candidate pair is aligned in two steps: statements by shape (a shortest edit script, Myers' algorithm), then tokens only between statements that differ, and only where two statements are at least 70% alike, so unrelated statements in the same place do not lend each other tokens. Pairs matching at least 80% of both bodies' tokens are near misses. Connected pairs form a class around the body most like the others. When an exact copy is most (70%) of each body, the exact copy is reported instead, as extracting it is the cleaner refactor.

## The same thing, written differently (C#)

`--semantic` adds the C# engine `dgf-dup-cs` ([crates/dog-food-dup/semantic](../crates/dog-food-dup/semantic/README.md)). It reduces each method to one canonical expression with the compiler: locals inlined, `if`/early return/`?:`/`switch` as one decision tree, comparisons with one polarity, loops as the LINQ they compute (`Sum`, `Count`, `Any`, `First`, `Max`, `Where`/`Select`, a sum per key). Methods with the same expression are type 4. It is sound first: a near miss (`>=` vs `>`, `First` vs `FirstOrDefault`, a dropped null check) is never called equal, and a method it cannot model is left out, not guessed at. Install it once:

```powershell
dotnet pack crates/dog-food-dup/semantic -c Release
dotnet tool install -g dgf-dup-cs --add-source crates/dog-food-dup/semantic/nupkg
```

Each project is compiled the way it builds:
- its SDK's implicit usings and its `<Using>` items;
- its packages, from `obj/project.assets.json`, so it needs a restore but not a build;
- the projects it references, transitively.

Where a package and the framework both carry an assembly, the newer one wins. `dgf-dup-cs --errors` lists the compile errors that leave methods out, and `--timings` shows how long each stage took.

With `--confirm`, each type-4 group is checked by running it, which is opt-in because it runs your code:
- The projects are compiled in memory, with their source generators run (`[GeneratedRegex]`, `[LoggerMessage]`).
- They load into their own context, and each method runs on the same 1,000 generated inputs. The inputs come from the parameter types and their nullability, the methods' own constants and the values either side of them, short lists and the usual edge values.
- Results are compared by value. A counterexample disproves the group: it is left out, and dgf-dup prints the input.
- Only methods without effects run: none of the project's own methods or constructors unless their bodies have no effects either, no files, network, console, processes or threads, no database, no clock or `Guid.NewGuid`. Others say why they were not run.
- Instance methods run on an object made without its constructor, with fields of one name holding the same value in both classes.

`dgf-dup-cs src --compare Type.A Type.B` runs two named methods the same way and prints the verdict.

### Repeated queries on a table

With `--semantic`, every LINQ query on `IQueryable<T>` (an EF Core `DbSet<T>`, or a query built on one) is also read on its own, wherever it is in a method, knowing which entity `T` it queries. Its filter is reduced to one form:
- lambda parameter names do not matter;
- `Where(a).Where(b)` is `Where(a && b)`, in any order, since EF Core turns both into SQL `AND`;
- `FirstOrDefaultAsync(pred)` is `Where(pred).FirstOrDefaultAsync()`;
- values from outside the lambdas (`request.ShopId`, `shopId`) become parameters.

Three kinds of repetition are reported, with the extension method that would replace them, built from the first query's own code so it compiles where it did:

| Kind | Example | Suggestion |
| --- | --- | --- |
| The same filter in several methods (two or more conditions, or three or more queries) | `o.ShopId == shopId && !o.IsDeleted` | `public static IQueryable<Order> ForShopNotDeleted(this IQueryable<Order> query, Guid shopId) => query.Where(...);` in `OrderQueries`, next to `Order` |
| The same whole query: filter, includes, order, projection | `.Where(...).OrderByDescending(o => o.PlacedAt).Select(o => o.Total)` | an extension returning the shaped `IQueryable<decimal>`; a repository or query method when every copy ends the same way |
| One condition in three or more different queries of a table | `!u.IsReversed` | a small named extension (`NotReversed()`) to combine; for a condition every query needs (soft delete, the tenant), EF Core's `HasQueryFilter` |

Conditions on the key alone (`x.Id == id`, `ids.Contains(x.Id)`) are left out: that is what `Find` is for. Names come from the conditions: `ForShop` (`ShopId == ...`), `NotDeleted` (`!IsDeleted`), `WithoutEndedAt` (`EndedAt == null`), `Confirmed` (`Status == Status.Confirmed`). They are suggestions to rename. Repeated queries do not count as duplicated lines and do not fail `--fail-on-copies`: they are advice. In the HTML page they are the *query* kind, with a "Tables queried the same way" chart.

## Measuring it

[crates/dog-food-dup/tests/corpus/csharp](../crates/dog-food-dup/tests/corpus/csharp/README.md) is a labelled C# corpus: copies (types 1-3), groups of methods that do the same thing written differently (type 4), near misses that do different things, and decoys. Running it checks its own labels on generated inputs. `cargo run -p dog-food-dup --bin dgf-dup-bench` scores `dgf-dup` on it, or any tool's JSON with `--report`.

| Run | Types 1-3 | Type 4 | Overall |
| --- | --- | --- | --- |
| `dgf-dup` alone | 14 of 15 | 1 of 47 | |
| with `--semantic` | 14 of 15 | 47 of 47 | recall 98%, no decoy or unrelated match, no near miss called equal |
| with `--confirm` | | all 17 groups confirmed by running | every near miss it can run (12 of 12) disproved by `--compare` |

Precision on real code is measured on hand-labelled scans of open-source repositories ([tests/corpus/real](../crates/dog-food-dup/tests/corpus/real/README.md)), scored with `dgf-dup-bench --real LABELS --report SCAN`. On dotnet/eShop it is 34 real findings of 35 (97%). It was 77% before generated files and nested copies were left out.

On a large ASP.NET Core backend (2,000 files, 25 projects), `dgf-dup --semantic` takes about 25 seconds. The two engines run at the same time, and the C# engine binds one method at a time on every core, skipping before binding the methods whose syntax already shows they will be left out.
